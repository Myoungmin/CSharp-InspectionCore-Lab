# DEV01 — 지속 개발 구조 보완

상태: Verified. 범위: M2 마무리와 M3a 착수 사이의 개발 운영 보완. 사용자 요청에 따라 검증 후 M2와 함께 커밋하고 다음 단계로 진행한다.

## 목표와 범위

작업 템플릿·목록·공통 완료 기준, 계약과 필수 테스트 사례의 대응표, 보류 항목과 재검토 기준을 추가한다. CI·스타일 변경·자동 제어기 구현은 이번 범위에 포함하지 않는다.

## 인수 조건

- 새 작업을 템플릿에서 시작하고 작업 목록에서 상태·증거를 찾을 수 있다.
- 기존 M1/M2의 42개 필수 사례를 클래스·메서드·사례 이름으로 확인한다. 전체 수를 유지해도 필수 사례가 사라지면 거절한다.
- 기존 테스트 최소 수·skip 금지·실제 DLL·콘솔·문서 기준을 유지한다.
- 보류 항목에 이유·재검토 조건·완료 증거를 기록한다.
- 전체 검증 후 커밋하고 M3a 작업을 시작한다.

## 아키텍처 결정

ADR: 기존 결정 유지. 제품 책임·포트·완료 경계·Native ABI를 바꾸지 않는 개발 운영 보완이다. [ADR 절차](../docs/adr/README.md)를 작업 템플릿에서 사용한다.

## 검증 계획과 정책 변경

기존 최소 실행 수 검사를 유지하고 정적 필수 사례 목록을 추가한다. 다른 테스트로 수만 채우는 경우를 막기 위한 강화다. 클래스·메서드·데이터 사례 이름 변경은 대응표와 변경 이유를 함께 리뷰한다. TRX 복사본의 필수 사례를 다른 이름으로 바꿔 총수 유지 상태에서도 거절하는지 확인한다.

## 증거와 리뷰

전체 검증이 통과했다. `artifacts/verification/20260927T004747Z-6b384103/summary.json`에 Core 19개·통합 23개·필수 사례 42개, 실제 콘솔·DLL·문서 결과가 있다. 필수 사례 이름만 바꾸어 전체 수를 유지한 TRX 복사본도 예상대로 거절했다. 해당 증거는 `artifacts/required-cases/c6354f1164364de9adea287ced246264`에 있다. 정책 코드와 대응표를 자체 리뷰했으며 별도 리뷰 세션을 수행한 것은 아니다. 이 기록 정리 후 최종 소스 검증도 별도 verification 폴더에 남긴다.
