# M3b — Native 작업·진행 콜백 종료와 자원 수명

상태: Verified. 기준 커밋: 08bec59. 구현 검증과 사용자 학습 확인은 구분한다.

## 목표와 범위

Native Start/RequestStop/Wait/Destroy와 진행 콜백을 구현한다. 실제 종료 전 해제 방지, 늦은 콜백, 종료 실패의 엔진 격리를 검증한다. 자동 반복·IPC·자동 재시도 제어기는 후속 작업이다.

## 인수 조건

- 실제 x64 DLL에서 입력을 복사하고 순서 있는 진행 통지를 전달한다. 이전 결과·콜백이 다음 실행에 섞이지 않는다.
- 취소와 Dispose는 작업 및 진행 콜백 종료를 기다린다. 저장·다음 실행·핸들 해제가 앞서지 않는다.
- 콜백 예외는 Native 경계를 넘지 않고 실행 오류로 전달한다. 자신의 콜백에서 동기 종료하는 재진입은 거절한다.
- Stop 오류는 Wait로 실제 종료를 확인한 후 엔진을 Faulted로 고정한다. Wait 오류는 종료 미확인 장애로 명시하고 자원을 프로세스 수명 동안 보존한다. 어느 경우도 새 실행을 받지 않는다.
- 기존 67개 사례를 보존하고 새 수명 계약을 [필수 대응표](../docs/verification-map.md)에 추가한다.

## 아키텍처 결정

[ADR-0008](../docs/adr/0008-native-async-lifetime.md)은 0005의 동기 수명 결정을 대체한다. [ADR-0009](../docs/adr/0009-termination-failure-quarantine.md)는 0007의 완료 규칙에 종료 미확인 장애를 명시한다. Core에는 플랫폼 독립 종료 예외만 추가하고 Native 선언은 Interop에 유지한다.

## 검증 계획과 정책 변경

실제 DLL의 콜백 진입·반환을 명시적 TaskCompletionSource 신호로 제어한다. 시간 초과는 수동 TimeProvider로 발생시킨다. integration 프로세스 종료 제한과 필수 사례 전부 실행 정책을 유지한다. ABI 버전 검사는 v1에서 v2로 갱신하며 기존 동기 Run export는 경계 회귀 테스트용으로 유지한다. Core 최소 수를 44→52, 통합을 23→35, 실제 DLL을 20→32로 올린다. 신규 20개(수명 12 + 종료 실패 8)는 M3B-001~010으로 고정하고 기존 67개는 유지한다. Host Native 진행 0~4 출력과 성공 로그 이전 완료 순서도 검증에 추가한다.

Wait 실패 주입 사례는 사용 여부가 불명확한 핸들 하나와 GCHandle을 의도적으로 테스트 프로세스 종료까지 보존한다. 누수 없는 정상 종료 테스트와 분리하며, 해당 프로세스를 재사용하거나 자동 복구하지 않는다.
