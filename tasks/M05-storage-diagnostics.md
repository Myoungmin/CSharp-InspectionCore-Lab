# M05 — SQLite 저장·검색과 구조화 진단

상태: Verified. 기준 커밋: c911ff6. 마일스톤: M5. 구현 검증과 사용자 학습 확인을 구분한다.

## 목표와 범위

JSON 실행 경로를 유지하면서 SQLite 저장을 선택하고 기간·판정·JobId 검색을 제공한다. 재시작 후 게시 결과 조회, 구조화 JSONL 진단과 저장·Native·IPC 장애 주입을 구현한다. 영속 RequestId 중복 방지, 실패 실행의 DB 이력과 Codex 제어기는 이번 범위가 아니다.

## 인수 조건

- 실제 SQLite 파일에서 저장·재시작 조회·기간/판정/JobId 검색과 안정된 커서 정렬을 확인한다.
- RunId 중복은 덮어쓰지 않는다. 트랜잭션 실패와 사전 취소는 새 결과를 남기지 않는다. 알 수 없는 스키마는 자동 변경하지 않는다.
- Host/Client 프로세스로 SQLite GetResult/SearchResults를 호출한다. 기존 JSON·Native·IPC 146개 필수 검증은 유지한다.
- 모든 자동 실행의 RunId·단계·종료 원인을 기록하고 RequestId/연결 ID와 연관 짓는다. 로그 실패가 실행 결과를 바꾸지 않으며 Host 종료 전에 기록을 마친다.
- 저장 실패의 계산 결과, Native 작업/상태 코드, 손상 IPC와 유실 응답을 구분해 추적한다.

## 아키텍처 결정

[ADR-0013](../docs/adr/0013-sqlite-results-and-query.md)은 SQLite와 조회 포트·IPC 검색을, [ADR-0014](../docs/adr/0014-structured-diagnostics.md)는 구조화 진단·오류 격리·장애 주입을 기록한다. 구현과 함께 ADR 목록·현재 계약·그림을 갱신한다.

## 검증 계획과 정책 변경

Microsoft.Data.Sqlite 9.0.20 한 패키지만 Infrastructure의 직접 생산 의존성으로 허용한다. .NET SDK/TFM/x64는 변경하지 않는다. 잠금 파일을 갱신하고 검증 스크립트의 패키지 예외를 정확한 이름·버전에 한정한다. 기존 146개는 제거하거나 약화하지 않는다. M5-001~023의 35개 사례(Core 조회 7·진단 4, SQLite 11, 프로세스 13)를 추가해 Core 94 + 통합 87 = 181개를 필수로 지정한다. 기준은 TRX에서 자동 생성하지 않고 인수 조건과 테스트 내용을 검토해 직접 작성했다. Native 34·기존 IPC 23 검사와 잠금 restore·CLI 실패 검증도 유지한다. 추가 최소 개수와 정확한 필수 사례는 새 계약 누락을 차단하기 위한 강화다.

Core 단위 테스트는 메모리 대역·명시적 신호를 사용한다. SQLite 실제 파일·트리거 실패·잠금은 통합 테스트에 둔다. IPC는 준비 출력·상태 응답으로 순서를 확인하고 기존 프로세스 제한 시간과 실패 시 정리를 유지한다. 최종 검증은 scripts/verify.ps1이다.
