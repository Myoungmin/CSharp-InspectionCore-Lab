# M3c 구현과 검증 기록

기준 커밋: d197d71. [작업](../tasks/M03c-auto-sequence.md), [자동 실행 계약](auto-contract.md), [ADR-0010](adr/0010-sequential-auto-admission.md)을 함께 읽는다. 구현 검증과 사용자 학습 확인은 구분한다.

## 구현

자동 세션이 반복 간격에도 접수를 예약한다. 수동과 자동은 같은 한 건 실행 경로를 이용하며 StopAuto는 예약만 중지하고 CancelRun은 현재 검사를 취소한다. 제품 Fail은 계속하고 실행 오류·취소·타임아웃은 반복을 중지한다. Native 종료 실패의 엔진 격리를 유지한다.

Host는 --repeat/--interval-ms로 유한 반복을 실행한다. 매 실행은 새 RunId로 JSON에 저장되며 콘솔은 세션 요약과 마지막 결과를 보여 준다. 자동 세션의 전체 실행 이력은 메모리에 쌓지 않는다.

## 실제 검증

전체 verify `20260927T054349Z-a92b6a75`에서 Core 83개와 통합 37개, 총 120개가 통과했다. 실패·skip은 0이다. 자동 Pass/Fail 4세션의 12파일과 기존 한 건 6파일, 저장 오류·타임아웃·인수 오류, ADR 10건·다이어그램 8개·링크까지 확인했다. 소스 식별 정보와 최종 재검증 절차는 작업 기록에 남겼다. 수동 TimeProvider와 작업 진입·반환 신호로 순서를 제어했고 실제 Native 콜백이 살아 있는 상황에서도 두 중지 동작을 비교했다. 테스트 시간 공급기의 System 이름 충돌은 using 지시문으로 해결했으며 테스트 기준은 낮추지 않았다.

## 직접 확인할 학습 항목

- 자동 대기 중 IsBusy=false인데 수동 Start가 Busy인 이유를 설명한다.
- StopAuto와 CancelRun을 어느 순서로 사용할지 판단한다.
- 저장 중 늦은 CancelRun이 반복을 중지하지 않는 이유를 설명한다.
- 같은 JobId에서 RunId와 AutoId가 어떤 수명을 식별하는지 설명한다.
- Native Wait 오류가 난 뒤 자동 재시작을 허용하면 안 되는 이유를 설명한다.

코드는 Codex가 구현했으며 사용자의 직접 설명·수정·재현은 아직 확인하지 않았다. 다음 단계는 M4 IPC다.
