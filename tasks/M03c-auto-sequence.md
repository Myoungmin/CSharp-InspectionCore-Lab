# M3c — 같은 Engine을 이용한 순차 자동 반복

상태: Verified. 기준 커밋: d197d71. 구현 검증과 사용자 학습 확인은 구분한다.

## 목표와 범위

StartAuto/GetAuto/StopAuto, 순차 반복과 수동 실행 배타 제어를 구현한다. 첫 실행은 즉시 접수하고 이후 실행은 직전 저장·정리 완료 후 지정 간격을 기다린다. Host에 유한 반복 CLI를 추가한다. IPC·SQLite·Codex 개발 자동 제어기는 후속 범위다.

## 인수 조건

- 실행 사이 대기에도 자동 세션이 예약을 유지한다. 수동·자동 동시 시작은 하나만 접수하며 큐를 만들지 않는다.
- 같은 JobId를 반복하되 각 실행에 새 RunId를 발급한다. 저장 완료와 취소·Native 종료 계약을 그대로 사용한다.
- StopAuto는 다음 예약만 막고 현재 실행은 유지한다. CancelRun이 실제 취소한 실행은 반복을 중지한다. Persisting의 늦은 취소는 기존처럼 TooLate다.
- 제품 Fail에는 계속하고 실행 오류·타임아웃·현재 실행 취소에는 반복을 중지한다. 종료 프로토콜 실패는 엔진 Faulted를 유지한다.
- Dispose는 예약을 닫고 현재 실행과 자동 루프 정리를 모두 기다린다. 옛 예약·세션의 명령이 새 세션에 영향을 주지 않는다.
- C# 및 실제 Native 반복 실행의 고유 결과 파일을 확인하고 기존 필수 87개 사례를 보존한다.

## 아키텍처 결정

[ADR-0010](../docs/adr/0010-sequential-auto-admission.md)에 자동 세션의 예약·주기·중지 계약을 기록한다. ADR-0006의 접수 범위를 확장·대체하고 ADR-0008·0009의 Native 수명과 종료 실패 계약은 유지한다.

## 검증 계획과 정책 변경

경합은 명시적 신호, 반복 간격·타임아웃은 수동 TimeProvider로 제어한다. 실제 시간에 의존한 sleep 테스트를 추가하지 않는다. Core 최소 기준을 52→83, 통합을 35→37, 실제 DLL을 32→34로 올린다. 신규 Core 31개와 Native 2개를 M3C 사례로 고정한다. 자동 예약·중지 흐름을 설명하는 auto-sequence 그림을 추가하여 필수 다이어그램을 7→8개로 확장한다. Host의 managed/native 각 Pass/Fail 3회 반복과 저장 실패·즉시 타임아웃·인수 오류도 별도로 검증한다. 기존 테스트를 삭제하거나 필수 기준을 낮추지 않는다. StopAuto가 저장 실패를 정상 중지로 가리지 않는 경합 사례를 추가하여 오류 우선순위를 검증한다.
