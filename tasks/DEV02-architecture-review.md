# DEV02 — M0~M6 전체 구성 검토와 후속 작업 구분

상태: Verified. 기준 커밋: 45792b8. 구현된 M0~M6를 검토하고 .NET 10 전환은 사용자 요청에 따라 보류한다. 이 작업의 Verified는 검토·문서 정리의 완료이며 후속 기능 구현 완료를 뜻하지 않는다.

## 목표와 범위

로드맵·실제 프로젝트·주요 실행 경로·검증 증거를 대조해 완료 범위와 후속 작업을 구분한다. 사용자 추가 요청에 따라 Codex 자동 반복 제어기·CI·장기 운영의 최소 범위와 선행 조건도 검토한다. 이번 작업은 구조 검토와 문서 정리이며 SDK 이전이나 새 기능을 구현하지 않는다.

## 인수 조건

- Core 경계, Runner/Engine 책임, Host 수명 관리, Native 호출과 IPC/저장 경계를 확인한다.
- M0~M6 구현 완료와 Codex 자동 제어기·CI·장기 운영·사용자 학습 완료를 구분한다.
- .NET 10 전환 보류와 재검토 조건을 README·로드맵·보류 목록에 일치시킨다.
- 구현과 어긋난 문서 항목을 정리하고 기존 217개 필수 검증을 유지한다.
- 제어기의 기준 보호, CI 도구 재현성, 장기 운영의 보존·복원·수명 경계를 검토해 우선순위와 완료 조건을 남긴다.

## 아키텍처 결정

ADR: 기존 결정 유지. [ADR-0002](../docs/adr/0002-windows-x64-toolchain.md)의 고정 도구 체계와 [ADR-0015](../docs/adr/0015-cpp-cli-transport-and-shared-lifetime.md)·[ADR-0016](../docs/adr/0016-cpp-cli-build-and-deployment.md)의 호출·빌드 경계를 유지한다. 전환 일정 보류는 현재의 기술 선택이나 계약 변경이 아니므로 새 ADR은 추가하지 않는다.

제어기·CI·장기 운영은 [검토 제안](../docs/development-operations-review.md)으로 남겼다. 공급자·프로세스 권한·로그 완료·복원 계약의 채택은 각 구현 작업에서 별도 ADR로 결정한다. 기존 ADR의 근거를 바꾸거나 기능이 구현된 것으로 기록하지 않는다.

## 검증 계획과 정책 변경

기준 커밋의 실제 구현과 최근 M6 검증 기록을 읽고 참조 검사·필수 검증을 실행한다. 코드·테스트·인수 기준을 변경하지 않는다. 최종 명령은 scripts/verify.ps1이다.

## 검증 증거와 리뷰

Core 포트·Runner·Engine/자동 반복, Host 조립·IPC dispatcher·JSONL sink, Native 수명과 SQLite 경로를 읽고 실제 참조 그림·계약·M6 검증 증거를 대조했다. 검토한 경계에서 현재 기능을 막는 구조적 변경 필요성은 확인하지 못했다. 로드맵의 C++/CLI 누락, 다이어그램 목록·서버 종료 순서, .NET 10을 다음 우선 단계로 적은 문구를 현재 구현과 사용자 요청에 맞춰 수정했다.

후속 검토에서는 후보가 검증 시작 전에 기준 파일을 수정하는 것을 차단할 제어기가 없는 점, 원격 CI가 없는 점, 동기 로그 I/O·보존·백업·재전송 한도가 장기 운영의 추가 범위인 점을 구분했다. 기존 테스트 통과를 이 후속 기능의 증거로 사용하지 않는다.

OpenAI Docs 스킬과 공식 비대화형 실행 문서, GitHub runner 이미지 목록, Microsoft.Data.Sqlite 백업 문서를 확인했다. 설치된 CLI 0.155.0-alpha.16.3의 version/exec help/review help를 읽었으며 실제 Codex 작성·리뷰 호출은 하지 않았다. 근거 링크는 검토 제안 문서의 각 주장에 연결했다. 이번 코드 검토는 자체 리뷰다.
