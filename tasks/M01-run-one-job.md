# M01 — 검사 한 건 실행과 JSON 저장

## 목표와 범위

M0의 솔루션 기반과 M1의 실행 가능한 첫 기능을 완성한다. 네 프로젝트, 고정 SDK·패키지, 문서와 검증 스크립트를 포함한다. Native·자동 실행·IPC·SQLite·자동 Codex 반복 제어기는 후속 단계다.

## 인수 조건

- JobId는 정의를, 새 RunId는 개별 실행을 식별한다. 입력을 검증·복사한다.
- Prepare → Acquire → Inspect → Persist를 순서대로 수행하고 단계 실패 후 다음 단계를 호출하지 않는다.
- 정상 입력은 Pass/100/불량 0, 불량 입력은 Fail/75/불량 1이다. 두 경우 모두 저장 성공 시 실행 성공이다.
- 저장 실패는 Faulted와 RunId·Persist 단계·계산 결과를 남긴다. 완성된 JSON이 없으면 성공으로 판정하지 않는다.
- 저장 전 취소는 저장을 차단하고 저장 시작 후 취소는 저장 결과를 덮어쓰지 않는다.
- MSTest 최소 19개가 실행·통과하고 skip은 없다. 템플릿의 빈 테스트는 포함하지 않는다.
- 실제 Host를 정상·불량·반복 실행해 JSON 내용과 서로 다른 RunId를 확인한다. 공백 경로, 저장 위치 오류, 잘못된 인수도 확인한다.
- MSBuild의 실제 프로젝트 참조, 네 다이어그램, SVG와 상대 링크가 검증된다.
- 첫 기준 커밋 후 새 checkout에서도 verify.ps1이 통과한다.

## 학습할 핵심 판단

1. 제품 판정 Fail이어도 실행은 성공일 수 있는 이유.
2. 저장 실패 때 계산 결과와 실행 성공을 구분해야 하는 이유.
3. Runner가 주입된 객체를 해제하지 않는 이유.

사용자 답변·직접 작성은 아직 수행한 것으로 기록하지 않는다. 후속 세션에서는 위 판단과 핵심 코드 한두 줄을 함께 확인한다.

## 증거

실제 실행의 summary.json, TRX, Host 로그·JSON, 소스 파일 해시 목록은 artifacts/verification 아래에 남는다. 새 checkout 검증은 별도 artifacts 디렉터리를 가진다. 기록은 [실습 문서](../docs/practice-M01.md)에 요약한다.
