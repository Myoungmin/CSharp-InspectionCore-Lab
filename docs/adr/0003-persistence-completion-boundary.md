# ADR-0003: 저장 완료를 실행 성공의 경계로 삼는다

- Date: 2026-09-27
- Status: Accepted

## Context

검사 계산이 끝나도 저장이 실패할 수 있다. 취소가 저장과 경합할 때 같은 실행을 성공과 취소로 번갈아 보고해서는 안 된다. 이미 수용한 M1의 한 건 실행 계약을 이번에 기록한다.

## Decision

Prepare → Acquire → Inspect → Persist를 모두 마쳐야 실행 성공이다. 제품 Fail은 유효한 판정이며 저장에 성공하면 실행은 Succeeded다. 저장 실패는 Faulted로 전달하고 RunId·단계·원래 오류·계산 결과를 보존한다.

취소 접수와 저장 진입은 실행별 같은 원자적 경계에서 판정한다. 먼저 접수한 취소는 저장을 막고, 저장에 진입한 뒤의 취소는 저장 결과를 바꾸지 않는다. 따라서 저장소에 호출자의 취소 토큰을 넘기지 않고 실제 저장 종료를 기다린다. JobId와 매 실행의 RunId를 구분한다.

## Alternatives

- 검사 계산 직후 성공 반환: 결과 파일이 없는 실행을 성공으로 알릴 수 있다.
- 저장에도 호출자의 취소를 계속 전달: 취소 시점에 따라 계산·저장·완료 보고가 엇갈리므로 이번 계약으로 채택하지 않는다.

## Consequences

성공은 결과 저장 완료를 뜻하며 늦은 취소는 저장 오류를 덮어쓰지 않는다. 저장 시작 이후에는 호출자 취소에 즉시 종료하지 않는다. 저장 작업의 별도 장애·종료 정책은 향후 요구에 따라 검토해야 한다. M3 엔진의 상태·타임아웃·Native 종료 완료는 아직 이 구현의 보장 범위가 아니다.

## Validation

Core 테스트는 명시적 비동기 신호로 저장 전·후 취소와 저장 실패를 검사한다. 단계 실패 뒤의 후속 호출도 차단되는지 확인한다. verify.ps1은 실제 저장 실패 시 Faulted/Persist와 계산 점수를 확인한다.
