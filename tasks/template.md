# 작업 ID — 제목

상태: Planned / InProgress / Verified / Deferred 중 선택. 기준 커밋과 관련 마일스톤을 기록한다. Verified는 구현 검증이며 학습 완료와 구분한다.

## 목표와 범위

해결할 문제, 구현할 행동과 이번에 제외할 범위를 적는다.

## 인수 조건

관찰 가능한 입력·결과·실패 동작을 적는다. 해당하는 필수 검증 ID를 [대응표](../docs/verification-map.md)에서 연결한다.

## 아키텍처 결정

관련 ADR을 연결한다. 새 결정이 없다면 `ADR: 기존 결정 유지`와 이유를 적는다.

## 검증 계획과 정책 변경

단위·통합·콘솔·문서 중 필요한 검증과 경쟁 순서를 제어할 신호를 적는다. 테스트·인수 조건·검증 기준을 변경한다면 이유와 보장 범위의 차이를 명시한다.

## 검증 증거와 리뷰

실제 명령·결과·검증 ID·소스 식별 정보와 리뷰 결과를 적는다. 계획한 검증을 실행한 것처럼 기록하지 않는다. 별도 리뷰 세션을 실행했는지도 구분한다.

## 남은 일과 학습 확인

잔여 문제는 [보류 목록](../docs/backlog.md)에 연결한다. 사용자가 직접 판단·작성한 내용과 Codex의 구현을 구분한다.

## 완료 확인

- 인수 조건과 필수 검증이 통과했다.
- 관련 ADR·현재 계약·그림·검증 대응표를 갱신했다.
- 최종 소스에 대한 검증 증거와 리뷰 결과를 남겼다.
- 남은 일과 학습 미확인 사항을 구분했다.
- 변경 범위와 커밋 대상을 확인했다.
